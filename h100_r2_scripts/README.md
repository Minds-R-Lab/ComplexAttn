# R2 revision H100 scripts

Three experiments requested by Reviewer 1 on ESWA-D-26-23857R1.
These scripts assume the `shard-mamba` branch of `github.com/Minds-R-Lab/ComplexAttn`
is checked out at `$REPO_ROOT` (default: `~/ComplexAttn`) with the same conda
environment (`shard_mamba`) used for the R1 runs.

All runners write to `$RESULTS_DIR/r2_<task>/` with the same JSON schema as R1,
so the manuscript tables can be regenerated by rerunning the existing
`scripts/build_tables.py` with the new JSON paths.

| Script | Reviewer point | Wall-clock on 1x H100 | Output path |
|---|---|---|---|
| `r2_09_mquake_baseline.sh` | R1.2 | ~1 h  | `r2_09/mquake_frozen_baseline.json` |
| `r2_07_layer_module_ablation.sh` | R1.3 | ~6 h  | `r2_07/layer_module_grid.json` (9 cells) |
| `r2_08_multi_seed_5preset.sh` | R1.5b | ~30 h | `r2_08/preset_s{0,1,2}.json` (15 cells) |

## Usage

```bash
# 1. activate env, source repo
cd $REPO_ROOT
conda activate shard_mamba
export PYTHONPATH="$REPO_ROOT:$PYTHONPATH"
export RESULTS_DIR="$REPO_ROOT/results_r2"
mkdir -p "$RESULTS_DIR"/{r2_07,r2_08,r2_09}

# 2. Run smallest first to catch regressions early
bash r2_09_mquake_baseline.sh   2>&1 | tee "$RESULTS_DIR/r2_09/run.log"

# 3. Then layer/module ablation
bash r2_07_layer_module_ablation.sh 2>&1 | tee "$RESULTS_DIR/r2_07/run.log"

# 4. Finally the long multi-seed run (nohup / tmux recommended)
nohup bash r2_08_multi_seed_5preset.sh > "$RESULTS_DIR/r2_08/run.log" 2>&1 &
```

## After all three finish

Pull the three JSON outputs into the manuscript tables:

- `r2_09`: fills the `[pending H100 cell]` in `tab:mquake` (manuscript §6.5).
- `r2_07`: new Section 6.6 `tab:layer-module-ablation`; stub table in the R2 response
  letter will be swapped for real numbers.
- `r2_08`: replaces the single-seed cells in `tab:ablation` (manuscript §6.5) with
  mean ± SEM; the surrounding paragraph will be rewritten accordingly.

All three scripts are idempotent (seed-pinned, deterministic data loading); rerunning
is safe if a run is interrupted.

## Fidelity to R1 setup

Shared across all three:

- `N = 500` sequential insertions.
- STEER defaults: `tau = 0.70`, `gamma = 20`, `v_steps = 25`, `v_lr = 5e-1`.
- GRACE-for-Mamba defaults: `epsilon_init = 1.0`, `epsilon_expand = 0.1`,
  `replace_mode = "substitute"`, `finetune_lr = 1e-3`, `finetune_steps = 25`.
- CounterFact: `counterfact_data = data/counterfact/counterfact-edit.json`.
- zsRE: `zsre_data = data/zsre/zsre_mend_eval.json`.
- MQuAKE: `mquake_data = data/mquake/MQuAKE-CF-3K.json`.

Monkey-patches / API knobs that mattered in R1 and are still needed in R2:

- `shard_mamba.wrappers._build_rewrite(fact, tokenizer)` must return the paired
  `(prompt, target_new)` tuples the mquake pipeline expects; the R1 chain had to
  reach in and rebind this because the vendored ROMBA code uses a different key.
- `shard_mamba.data.counterfact_loader` reads from `counterfact-edit.json`, NOT
  `counterfact_full.json`; the latter has duplicated `case_id`s and corrupts the
  stream index.
- `v_steps` (not `n_v_steps`) is the kwarg on `SteerEditor.insert`. The R1 chain
  silently used the default when passed the wrong name.
